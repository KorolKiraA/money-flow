# MoneyFlow

Ядро финтех-приложения: **конвертер валют** с прогрессивной комиссией и **мультивалютный кошелёк**. Курсы — официальные, Центрального банка РФ. Все денежные вычисления идут на `BigDecimal` с банковским округлением — та же дисциплина, что в платёжных системах: никаких `0.1 + 0.2 != 0.3`.

## Идея проекта

Любой обменник, мультивалютная карта или бухгалтерия с валютными операциями решают три задачи: конвертация по кросс-курсу, комиссия, которая зависит от суммы, и ответ на вопрос «сколько всего у меня денег в пересчёте на одну валюту». MoneyFlow реализует все три как связанное ядро:

| Механизм | Что даёт |
|---|---|
| Кросс-курсы через рубль | любая пара валют, без таблицы «каждая с каждой» |
| Прогрессивная комиссия | чем крупнее операция, тем ниже процент — как в реальных тарифах |
| Мультивалютный портфель | все операции сразу отражаются в кошельке с итогом в RUB |
| Эффективный курс | пользователь видит реальную цену сделки после комиссии |

## Быстрый старт

Нужны **JDK 17+** и **Scala 3** через [scala-cli](https://scala-cli.virtuslab.org/) (`winget install VirtusLab.ScalaCLI`).

```bash
git clone https://github.com/KorolKiraA/money-flow.git
cd money-flow

scala-cli run MoneyFlow.scala
```

## Курсы и комиссии

Курсы к рублю — официальные данные ЦБ РФ ([cbr-xml-daily.ru](https://www.cbr-xml-daily.ru/daily_json.js)), зашиты в код на 07.11.2026: USD 82.14, EUR 92.19, CNY 12.27, KZT 0.18, AED 22.37. Конвертация любой пары идёт через рубль: `сумма × курс(from) ÷ курс(to)`.

Комиссия зависит от размера операции (пороги в USD-эквиваленте):

| Сумма операции | Комиссия |
|---|---|
| до $100 | 3,0% |
| до $1 000 | 2,0% |
| до $10 000 | 1,5% |
| свыше $10 000 | 1,0% |

Сетка — обычный список пар `(порог, ставка)`, легко заменить на тарифы конкретного сервиса.

## Почему BigDecimal

`Double` хранит числа в двоичном виде, и `0.1` в нём не представима точно. Для денег это недопустимо: копейки начинают «плавать» уже на второй операции. Поэтому весь MoneyFlow построен на `BigDecimal`:

- суммы, курсы и комиссии — только `BigDecimal`;
- округление — явное, `HALF_UP` (банковское правило «5 вверх»), до 2 знаков на деньгах и 4 на курсах;
- итог портфеля тоже округляется явно, а не «как получилось».

## Как это устроено

```
money-flow/
├── MoneyFlow.scala       # курсы, тарифы, конвертация, кошелёк, CLI
├── .github/workflows/ci.yml  # компиляция на каждый push
├── LICENSE
└── README.md
```

**Ключевые решения в коде:**

- `convert()` возвращает `Option[(нетто, комиссия)]`: неизвестная валюта — это `None` и вежливое сообщение, а не исключение;
- выбор ставки — `feeTiers.find(...)`: первый подошедший порог определяет комиссию;
- кошелёк — `mutable.Map` со значением по умолчанию `0`: пополнение валюты, которой ещё не было, не требует отдельной ветки;
- каждая конвертация атомарно списывает одну валюту и зачисляет другую — промежуточного «нулевого» состояния в портфеле не бывает.

## Проектные решения и ограничения

- **Курсы зашиты в код**, а не подтягиваются при старте. Это осознанно: ядро тестируется без сети. Для продакшена — загрузка JSON ЦБ при запуске (в идеях для развития).
- **Кошелёк живёт в памяти** и обнуляется при выходе: персистентность не входила в задачу ядра.
- **Комиссия списывается в рублёвом эквиваленте** из суммы операции — модель «комиссия включена», а не «сверху».
- **Нет отрицательных лимитов**: кошелёк честно уйдёт в минус, если конвертировать то, чего нет. Для учебного ядра это фича (видно стоимость операции), для боевого — нужна проверка остатка.

## Частые проблемы

| Проблема | Решение |
|---|---|
| `Неизвестная валюта!` | доступны только RUB, USD, EUR, CNY, KZT, AED; регистр не важен |
| Крякозябры вместо кириллицы | Windows Terminal, либо `chcp 65001` перед запуском |
| Сумма не принимается | дробную часть вводите через точку или запятую, без пробелов: `1000.50` |
| `scala-cli: команда не найдена` | `winget install VirtusLab.ScalaCLI`, затем переоткрыть терминал |

## Идеи для развития

- загрузка актуальных курсов ЦБ при старте (JSON API, кеширование на день);
- проверка остатка и отказ от операции при недостатке средств;
- история операций с сохранением в CSV;
- поддержка произвольной базовой валюты портфеля, а не только RUB;
- REST API поверх ядра (http4s) — превращение в микросервис обменника.
